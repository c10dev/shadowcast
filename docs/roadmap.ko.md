# 로드맵

[English](roadmap.md)

지금 목표는 **검사**다. 산문에서 장면의 물리 상태를 다시 세우고 동선 · 접촉 · 물건 연속성 오류를 찾는다. 이 문서는 검사가 끝났다고 볼 기준과 그 뒤 마일스톤을 정한다.

상태: 계획. 아래 결정 1~5 는 정해졌다. "추정"이라고 적은 비용과 크기는 재지 않은 값이다.

## 지금까지

시범 세트 v2: `data/scenes-v2-pilot.json`, 11장면, 37항목(정상판 11, 오류판 26), 4~7문장, 인물 1~2명. 조건별 정확도(A / B / C):

| 모델 | A | B | 프롬프트 변경 전 C | `e136682` 뒤 C |
|---|---|---|---|---|
| Gemini 4 Argon | 0.973 | 0.973 | 1.00 | 돌리지 않음 |
| Claude Opus 5.5 | 0.973 | 1.00 | 0.919 | 1.00 |
| Claude Sonnet 5.5 | 0.919 | 0.946 | 0.865 | 0.730 (헛경보율 0.455) |

출처: `results/run-v2-20261027-1718*`(A, B, 변경 전 C), `results/run-v2-20261027-173035-*` · `results/run-v2-20261027-173516-*`(변경 뒤 C).

읽을 것:

- 시범 세트로는 제안한 헛경보 한도 0.1 을 검증할 수 없다. 정상판 11개에서 헛경보가 0개여도 95% Wilson 상한은 0.26 이다.
- 조건 B 와 C 는 모델에 정답 시작 상태를 준다. Canon 실사용에는 정답 시작 상태가 없다.
- 같은 37항목에서 프롬프트 두 줄이 Opus 를 올리고 Sonnet 을 내렸다. 채점 항목을 보고 고친 프롬프트는 그 항목에 맞춰질 수 있다. 다음 세트는 dev 와 test 를 나눈다.

## 검사가 끝났다고 보는 기준

### 세트 v3

| 항목 | 목표 |
|---|---|
| 장면 | 40개 이상, 장면마다 20~40문장 |
| 인물 | 장면 절반 이상에 3명 이상 |
| 정상판 | 40개(정상 문장 약 1,000개) |
| 오류판 | 100개 이상 |
| 규칙별 | `not_held` 를 뺀 규칙마다 오류판 6개 이상 |
| 난이도 | `implicit` 50% 이상 |
| 기억 거리 | 원인이 15문장 넘게 앞에 있는 오류 20개 이상 |
| 접촉 · 향한 쪽 | 오류 30개 이상 |
| 실제 작가 모델 오류 | 다시 쓴 것 30개 이상("데이터 원칙") |
| 나누기 | dev 15장면, test 25장면. 프롬프트는 dev 만 보고 고친다 |

### 조건 D

조건 D 를 더한다. 문단과 인물 목록만 주고 시작 상태는 주지 않는다. Canon 이 실사용에서 줄 수 있는 것이다. A · B · C 가운데 가장 좋은 조건 옆에 D 를 함께 낸다.

### 지표

test 쪽에서 목표 모델 Gemini 로, 가장 좋은 조건과 조건 D 에서 잰다.

| 지표 | 한도 |
|---|---|
| 재현율 | 0.8 이상. 오류판 100개에서 0.79 면 95% 하한이 0.70 이다 |
| 정상판 기준 헛경보율 | 0.1 이하 |
| 정상 문장 100개당 헛경보 | 1개 이하 |
| 위치 정확도 | 0.9 이상 |
| 규칙별 재현율 | 규칙마다 0.6 이상. 한 채널을 통째로 놓치지 않게 한다 |
| 반복 안정 | 같은 설정을 두 번 돌려 정확도 차이 0.03 이하 |
| 비용 | 화 하나 검사가 Canon 검수 1회 비용을 넘지 않는다 |

작가는 항목이 아니라 화 단위로 경고를 보므로 문장 단위 헛경보 한도가 필요하다. 화 하나를 120문장으로 추정하면 한도에서 화당 헛경보는 1~2개다.

### 세트 타당성

세트가 모델을 갈라야 한다. Sonnet 이나 gemma 가 Gemini 보다 0.1 이상 낮아야 한다. 이 기준이 예전 1단계 조건 "가장 강한 모델도 만점을 받지 못한다"를 대신한다. 실제적인 세트에서 Gemini 가 만점이면 검사가 되는 것이지, 세트가 쉽다는 뜻이 아니다.

### M1. Canon 연결, 그림자 모드

- 목표: 실제 Canon 화에 지금 검수와 나란히 검사기를 돌린다. 경고와 경고마다 작가의 판정을 모은다.
- 산출물:
  - 화를 장면으로 나눈다. 장면 경계에서 상태를 비운다.
  - 시작 상태는 Canon `CharacterState.attire` 에서 받는다. Canon 에 없는 칸은 모름이다.
  - Canon 연구 화면(`TRIAL_MODES`)의 `shadow` 방식, 그다음 Canon 검수 경로의 선택 방식.
  - 작가 판정(맞음 · 헛경보)이 붙은 경고 수집함.
- 먼저 지금 Canon 검수를 오류 갈래(몸 · 접촉 · 물건)별로 잰다. 갈래별 기준선이 아직 없다.
- 데이터: Canon 시험 작품만 쓴다(결정 3). 실제 오류는 다시 쓴 뒤에만 공개 세트에 넣는다.
- 연결 코드는 Canon 저장소에 둔다.

### M2. 고치기 제안

- 목표: 위반마다 고친 안 1~2개를 낸다. 엔진이 각 안을 다시 추출하고 검사한다. 위반이 사라지고 새 위반이 없는 안만 작가에게 보인다.
- 범위(결정 4): 오류 문장을 바꾸고, 필요하면 바로 앞에 한 문장을 넣는다. `hand_full` 은 먼저 내려놓는 문장이 있어야 고쳐지는 경우가 많다.
- 산출물: shadowcast 의 고치기 프롬프트와 검증 고리, Canon 부분 수정 도구 연결.
- 고친 크기도 잰다: 문장에서 바뀐 부분의 중앙값.

### M3. 상태 채널 넓히기

- 후보: 자세(서기 · 앉기 · 눕기), 옆 자리(옆에 멘 가방), 시선, 키 높이.
- M1 수집함의 채널 밖 오류 가운데 15% 이상을 차지하는 채널만 넣는다. M1 데이터가 없으면 자세부터 넣는다.
- 채널마다 사건, 규칙, 오류판 8개 이상을 둔다. 장면 형식은 v3 가 된다.
- 프롬프트 두 줄로 Sonnet 이 0.865 에서 0.730 으로 내려갔다. 채널마다 dev 와 test 에서 점수 하락을 본다.

### M4. 쓰기 전 상태 주기

- 목표: 작가 모델에 장면 상태를 주고 오류가 줄어드는지 잰다.
- 여기서 검사기는 측정 도구다. 헛경보가 낮다는 것을 안 뒤에 시작한다.
- Canon 에서 상태 블록은 고정 블록 뒤에 둔다. 그래야 프롬프트 캐시가 계속 맞는다.
- 결정 5: Canon 기본으로 켜는 것은 측정 뒤에 정한다.

### M5. 싼 추출기

- M1 의 화당 비용이 한도를 넘거나 자동 집필 비용이 문제가 될 때만 시작한다(결정 5).
- 먼저 v3 에서 gemma 를 잰다. 모자라면 합성 데이터로 학습한다: 엔진이 사건을 만들고, 모델이 문장을 쓰고, 엔진이 라벨을 단다.

### M6. 공개 벤치마크

- test 쪽은 비공개로 두어 학습 데이터에 섞이지 않게 한다.
- 영어 세트는 번역이 아니라 새로 쓴다. 한국어의 주어 생략과 조사는 추출을 어렵게 하는 요소의 일부다.
- 공개와 영어 세트는 나중에 정한다(결정 5).

## 합치거나 옮긴 후보

- 긴 장면과 실제 작가 모델 오류는 따로 마일스톤을 두지 않고 검사 완료 기준에 넣었다.
- 화와 화 사이의 상태는 엔진 범위 밖이다([README](../README.md) 의 범위 표). M1 은 Canon 에서 시작 상태를 읽는다. M4 는 끝 상태를 Canon 에 제안할 수 있다. 저장은 Canon 이 한다.

## 데이터 원칙

- 실제 원고, 성적 내용, 미성년으로 보이는 인물은 데이터로 쓰지 않는다.
- 실제 작가 모델 출력의 오류는 다시 쓴다. 오류 유형만 세트로 옮긴다.
- API 키는 git 이 무시하는 `.env` 에만 둔다.
