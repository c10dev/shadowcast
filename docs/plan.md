# 실행 계획

상태: P1 구현 완료, P2 도구·예비 분석 완료. 사람의 원인 확정과 P3 이후는 대기. 갱신일: 2026-11-15 (KST).

목표는 실제 원고에서 오류 위치와 근거를 제시하면서 헛경보를 줄이는 검사기를 고르는 것이다. 현재는 A를 기준선으로 두고, B/C/D의 추가 상태 정보와 규칙 판정이 주는 이득을 측정한다. JEPA 실험은 별도의 진입 조건을 만족한 뒤 진행한다.

이 문서는 다음 작업의 순서를 관리한다. 모듈 책임은 [설계](design.md), 채점 규칙은 [평가 명세](evaluation.md), 연구 가설은 [JEPA 노트](research/jepa.md)에 둔다. 기존 README의 단계 0~4와 실험 기록은 프로젝트의 장기 목표와 이력을 설명한다.

정답 사건의 만점은 규칙과 주석의 일관성 검사다. 자연어 이해나 실제 원고에서의 일반화 검증으로 해석하지 않는다.

## 단계와 산출물

### P0. 문서 계약 정리 — 완료

- 용어집, 현재 장면 형식, 제안 모듈 설계, 평가 명세, 실행 계획, JEPA 연구 노트의 책임을 나눈다.
- README에서 문서 안내로 진입할 수 있게 한다.
- 현재 구현과 미구현 제안을 표시한다.

### P1. 평가 분리와 실패 처리 — 완료

의존성: P0.

변경 대상: `shadowcast/runner.py`, 새 `shadowcast/evaluation.py`, 관련 평가 테스트. 기존 프롬프트·규칙·데이터는 이 단계에서 평가 변화의 비교 기준으로 둔다.

작업:

1. 기존 채점 함수를 순수 평가 모듈로 분리한다. 기존 호출부는 작은 위임 함수로 호환할 수 있다.
2. 호출/형식 상태와 본문 판정을 구분하고 실패를 TN으로 계산하지 않는다.
3. 평가 명세의 완료율·정답 문장 검출률·헛경보 지표와 분모를 출력한다.
4. 기존 지표와 새 지표를 버전으로 구별한다. 과거 점수 재현 경로를 유지한다.

완료 기준:

- 정상판 호출 실패, 오류판 호출 실패, 다른 문장만 경고, 위치 없는 경고, 분모 0, 판단 보류를 다루는 테스트가 통과한다.
- gold/baseline 동작과 기존 조건 입력에 회귀가 없다.
- 새 결과만 보아도 정상판·오류판 각각 몇 개를 실제 판정했는지 알 수 있다.
- 검증은 가짜 백엔드와 정답 데이터로 수행한다. 유료 모델 재실행은 필요하지 않다.

### P2. 오프라인 재채점과 원인 분석 — 도구·예비 검토 완료, 사람 검토 대기

의존성: P1.

변경 대상: 새 `shadowcast/analysis.py`, `shadowcast/__main__.py`, 관련 호환 읽기·CLI 테스트. 구현 명령은 `rescore`, `audit`이며 원본 추출이 필요한 `replay`는 입력 대응 검증을 갖춘 뒤 추가한다.

작업:

1. 명시적으로 선택한 저장 결과를 읽어 새 지표를 산출한다.
2. 원본·분석 결과를 연결하고 원본 파일을 보존한다.
3. v3 dev의 C/D 정상판 경고 목록에 본문·사건·상태 근거를 붙인다.
4. 사람이 검토한 원인표와 미해결 항목 목록을 작성한다.

완료 기준:

- 네트워크와 SDK가 없어도 실행된다. 캐시 누락을 모델 호출로 보충하지 않는다.
- 원본 예측을 고정한 재채점과 규칙을 바꾼 재실행이 다른 작업으로 기록된다.
- 같은 입력·평가 버전의 점수는 재현되며, 원본 보고서·캐시의 내용은 바뀌지 않는다.
- dev의 대상 헛경보 항목이 모두 검토되거나 근거 부족 사유와 함께 `unresolved`로 남는다.
- 원인별 경고 수와 독립 원인 수를 바탕으로 다음 수정의 우선순위를 결정한다.

P1/P2의 첫 구현 묶음으로 평가 코드, 오프라인 명령, 재채점 보고서와 [예비 원인표](analysis/2026-11-14-p1-p2.md)를 작성했다. 3개 모델의 C/D 정상판 경고 50항목을 조사했고, 29항목에 원인 후보를 기록하고 21항목은 사유와 함께 `unresolved`로 남겼다. 현재 규칙의 재현 불일치 15, 추출/사건 불완전 5, 계약 미확정 1항목이다. 후보 유형과 경고 문장 수는 보고서에 구분했으며, 사람의 원인 확정 및 독립 원인 건수 확정은 미완료다. 추출 프롬프트는 변경하지 않았다. 각 미해결 유형의 후속 근거와 종료 조건은 [상세 계획](plans/p3-state-rules.md#p2에서-남은-검토)에 둔다.

### P1/P2 검증 기록 — 2026-11-15 (KST)

| 검사 | 결과 |

정답 사건 검증은 모듈 분리의 회귀 검사다. 모델 성능 향상을 뜻하지 않는다. 실제 공급자 호출은 실행하지 않았다. 다음 구현은 P3의 명시적 손/미확정 손 처리부터 진행한다.

### P3. 상태 해석과 동일성 수정 — 대기

의존성: P2 도구·예비 분석. 최소 사건열로 확인할 수 있는 계약 위반은 사람의 전체 원인표 검토와 별개로 진행한다. 본문 해석이 갈리는 사례는 해당 계약을 정한 뒤 수정한다. 작업 단위와 대조 사례는 [P3 상세 계획](plans/p3-state-rules.md)에 둔다.

변경 대상: `shadowcast/rules.py`, 필요할 경우 사건 변환 코드, 규칙 테스트. 대규모 상태 스키마 변경은 별도 작은 작업으로 나눈다.

작업:

1. `state.hand`를 무시하는 경우부터 재현하고 손의 명시적 배정과 미확정 배정을 구분한다.
2. 물체·장소 비교에서 같음·다름·미확정을 구분하고 명시적 별칭을 존중한다.
3. 건네기, 양손 점유, 접촉, 실패 이후 동작과의 조합을 점검한다.
4. 캐시가 검증된 항목만 같은 추출 응답으로 전후 규칙을 비교한다.

`audit`는 정상판 경고 진단만 제공하므로 전체 성능 비교에 충분하지 않다. 오류판을 포함한 전체 대상의 오프라인 재실행 경로는 P3-5에서 별도 구현한다. 변경 전 현재 코드의 결과를 기준선으로 기록해 과거 규칙 버전 불명 문제와 분리한다.

완료 기준:

- 설계 문서의 손 네 사례와 칼/칼집·좌우 주머니·덜 구체적인 장소 사례가 통과한다.
- 헛경보를 줄이면서 명시적인 손 충돌이나 장소 모순을 놓치지 않는다.
- 전체 규칙 테스트와 정답 데이터 검증이 통과한다. 기존 정답과 충돌하면 데이터 오류인지 계약 변화인지 먼저 기록한다.
- 바뀐 결과마다 원인을 설명할 수 있다. 성능을 올리려고 test 정답을 바꾸지 않는다.

### P4. 실제 원고에 가까운 비교 평가 — 대기

의존성: P2. P3 결과가 준비되면 개선한 C/D를 포함한다.

작업:

1. 공개 가능한 문단과 실제 집필 오류를 재작성한 사례를 모은다. 출처와 공개 가능 여부를 기록한다.
2. 정상 장면의 생략·손 미지정·함께 이동·옷을 벗은 뒤의 상태처럼 헛경보에 취약한 사례를 포함한다.
3. 정상/오류 변형과 패러프레이즈를 원본 장면 단위로 묶어 분할한다.
4. 기존 test는 고정 회귀 세트로 남기고 새 최종 평가 세트는 설정을 확정할 때까지 열람하지 않는다.
5. A, 신뢰할 시작 상태가 있을 때의 B, 준비된 C/D를 같은 항목에서 비교한다.

완료 기준:

- 정답은 규칙 엔진의 통과 여부와 별도로 사람의 본문 검토를 받는다.
- 평가 표본 수, 완료율 목표, 반복 횟수, 비용 한도, 신뢰구간을 포함한 채택 기준을 최종 평가 전에 고정한다.
- 근거 타당성을 검토하고 비용·지연·헛경보·정답 위치 검출을 함께 보고한다.
- A보다 이득이 확인된 구성만 제품 후보로 선택한다. 신뢰할 시작 상태를 얻는 비용도 포함한다.

### R1. JEPA 비교 실험 — 조건부 대기

의존성: P4와 [연구 진입 조건](research/jepa.md)의 충족.

동일한 데이터·분할·예산에서 지도학습 추출기와 JEPA 목적을 추가한 모델을 비교한다. 기존 v3 dev/test를 학습 데이터로 사용하지 않는다. JEPA가 검사 성능 또는 비용에 추가 이득을 보이지 않으면 제품 경로에 넣지 않는다.

## 진행 시 지킬 경계

- 기본 모델·인증·가격·SDK 설정 변경은 평가 모듈화에 섞지 않는다.
- `hand-check/`의 종료된 실험을 새 구조에 맞추기 위해 재작성하지 않는다.
- 프롬프트 변경, 규칙 변경, 평가 변경을 서로 다른 실험 변수로 기록한다.
- 커밋·배포·Canon 연결은 이 문서 정리 작업의 산출물이 아니다.
- 각 구현 묶음은 관련 테스트, 필요한 데이터 검증, 변경 범위 확인으로 끝낸다. 통과한 검증을 이유 없이 반복하지 않는다.
