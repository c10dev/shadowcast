# 평가 및 오프라인 분석 명세

상태: 주 지표 v2와 `rescore`/`audit` 구현. 엄격한 상태 지표·독립 `replay`·사람의 원인 확정은 후속 작업. 2026-11-15 (KST).

[검사 결과 계약](design.md)을 기준으로 한다. 평가 방식이 바뀌면 `metrics_version`을 바꾸고 과거 수치와 나란히 표시한다.

## 평가 집합과 실패 처리

- 전체 시도 항목: 명시한 실행 보고서에 실제 포함된 항목. `--limit` 실행을 전체 데이터 평가로 표시하지 않는다.
- 유효 응답: `status=ok`인 항목. `undetermined`도 유효 응답에는 포함된다.
- 판정 완료: 유효 응답 중 `verdict=error` 또는 `no_error`인 항목.
- 호출 실패, 잘못된 출력, 판단 보류는 정상 판정(TN)이 아니다.
- 현재 실행기는 항목당 한 번 호출하고 `retry_policy`에 이를 기록한다. SDK 내부 재시도는 별도 항목 trial로 노출되지 않으며 총비용도 완전히 추적하지 못한다. 후속 재시도 기능은 같은 항목·조건·trial의 시도별 기록, 최종 선택 정책, 모든 시도의 비용을 포함해야 한다.

완료된 항목만 평가하면 실패가 많은 모델에 유리할 수 있다. 따라서 조건별로 전체 항목 수, 정상/오류 수, 호출 실패 수, 잘못된 출력 수, 보류 수, 판정 완료율을 먼저 보여준다. 정상판·오류판의 완료율도 따로 표시한다.

## 주 지표

| 지표 | 분자 / 분모 | 실패·보류 처리 |
|---|---|---|
| 판정 완료율 | 판정 완료 항목 / 전체 시도 항목 | 완료에서 제외 |
| 전체 기준 정답 문장 검출률 | 정답 오류 문장을 경고한 완료 오류판 / 전체 시도 오류판 | 분모에 남으며 미검출 |
| 완료 기준 정답 문장 검출률 | 위와 같은 분자 / 판정 완료 오류판 | 분모에서 제외, 완료율과 함께 표시 |
| 완료 기준 헛경보율 | 경고한 완료 정상판 / 판정 완료 정상판 | TN으로 세지 않음 |
| 정상 100문장당 헛경보 | 완료 정상판의 중복 제거 경고 문장 수 × 100 / 완료 정상판 문장 수 | 미완료 정상판 제외, 해당 문장 수도 표시 |
| 문장 경고 정밀도 | 정답 위치와 일치한 경고 문장 수 / 완료 항목의 전체 경고 문장 수 | 주석이 완전한 평가 항목에서만 산출 |

분모가 0이면 값은 `null`로 표시한다. 0%나 100%로 임의 변환하지 않는다. `error`인데 위치가 없는 기존 응답은 항목 헛경보에는 반영하지만 문장 경고 수를 만들어내지는 않는다. 위치 정보가 없는 경고 항목 수를 함께 표시하고, 문장 기반 집계는 불완전한 값임을 명시한다.

현재의 항목 `recall`, `accuracy`, `precision`, `f1`은 과거 비교용으로 유지할 수 있다. 오류판의 다른 문장에 경고한 경우에는 항목 recall만 맞고 정답 문장 검출은 실패다. 새 주 지표와 이름을 혼용하지 않는다.

`rule_accuracy`는 기존 응답의 항목 전체 규칙을 이용한 값으로 보존한다. 여러 경고 각각의 규칙을 알 수 없는 과거 결과에서 문장별 규칙 정확도를 추정하지 않는다. 근거의 타당성은 별도의 사람 검토 항목이며 자유 서술 문자열 일치로 채점하지 않는다.

## 채점 예시

정상판 2개 중 하나는 `no_error`, 하나는 호출 실패다. 오류판 2개 중 하나는 정답 문장을 경고했고, 하나는 다른 문장만 경고했다.

- 판정 완료율: 3/4. 정상판 완료율: 1/2. 오류판 완료율: 2/2.
- 전체 기준 정답 문장 검출률: 1/2.
- 완료 기준 헛경보율: 0/1. 실패한 정상판을 포함한 0/2로 보고하지 않는다.
- 두 경고가 각각 한 문장이라면 문장 경고 정밀도: 1/2.
- 과거 항목 recall: 2/2. 이 수치를 실제 오류 위치 검출률이라고 부르지 않는다.

## 상태 추출 평가 — 엄격한 지표는 미구현

기존 채널 점수는 손의 빈칸 수, 최외곽 옷 등 축약된 값이다. 새 점수는 `legacy` 점수와 구별하고 정상판에서 우선 계산한다. 정답 자체가 불확실한 칸은 확정 정답으로 만들지 않는다.

| 채널 | 비교 단위 |
|---|---|
| 손 | 인물·문장·좌우 손별 물체/사람 식별자 또는 명시적 빈손 |
| 방향 | 인물 쌍별 방향 |
| 착용 | 부위별 알려진 전체 겹침 순서 |
| 공간 | 몸 앞뒤에 있는 대상 집합 |
| 물건 위치 | 알려진 소유·손·착용·외부 장소를 구분한 위치 |

정답이 확정된 칸에서 예측이 미지이면 불일치다. 정답 미지는 정확도 분모에서 제외한다. 정답이 확정된 칸 중 예측도 확정한 비율을 함께 보고해, 모름이 빈손처럼 점수를 얻지 않게 한다.

정답 자체가 여러 가능한 손 배정을 허용하면 한 임의 배정과의 정확 일치를 요구하지 않는다. 확정 칸 점수와 제약 양립 여부를 분리한다. 이를 평가하려면 정답 주석과 상태 표현도 미확정을 지원해야 하므로 첫 재채점 단계에서는 산출 불가로 둔다.

C와 D의 정답 상태열은 각 조건이 실제 받은 시작 정보에서 계산한다. D 점수가 C와 같은 정보 복원 능력을 측정한다고 해석하지 않는다. 물건이 손에 들어가 외부 장소 목록에서 빠진 것을 곧 위치 미지로 취급하지 않는다.

저장된 채널 합계만으로 좌우 손·물체 이름·전체 옷 순서를 복원할 수 없다. 엄격한 상태 지표에는 원본 사건 추출과 상태 재실행이 필요하다.

## 오프라인 작업 세 가지

| 작업 | 입력 | 바꾸는 것 | 필요한 근거 |
|---|---|---|---|
| 재채점 `rescore` | 저장된 정답·예측 행 | 평가 공식과 실패 분류 | 원본 보고서, 평가 버전 |
| 재실행 `replay` | 캐시의 원본 추출 응답·해당 데이터 | 사건 변환·규칙·상태 평가 | 정확한 항목/요청 대응, 데이터, 변환·규칙 버전 |
| 원인 분석 `audit` | 원본 본문·정답·예측·가능하면 사건/추적 | 검토 목록과 원인 주석 | 근거 문장·이벤트·원본 참조 |

`rescore`와 `audit`를 구현했다. 독립 `replay` 명령은 아직 없다. `audit`의 상태 추적은 현재 규칙으로 수행한 진단 재실행이며 새 성능 점수나 과거 규칙 재현으로 표시하지 않는다.

```bash
python3 -m shadowcast rescore ORIGINAL.json --output NEW-rescore.json
python3 -m shadowcast audit ORIGINAL.json --data data/scenes-v3-dev.json --cache results/cache --output NEW-audit.json
```

과거 행에는 주석 완전성 표시가 없으므로 문장 정밀도는 기본 `null`이다. 단일 오류 주석이 완전하다고 명시적으로 가정할 때만 `rescore --complete-annotations`를 쓴다. 새 실행의 현재 단일 오류 장면 형식에는 `annotation_complete=true`를 기록한다. 출력 경로가 이미 존재하면 거부한다.

새 실행 보고서는 `conditions.<조건>.metrics`와 `legacy_metrics`를 구분한다. 재채점 보고서는 원본의 `original_metrics`와 버전도 보존한다. `audit`는 저장된 전체 요청 문자열·응답 메타데이터 및 제공된 해시를 검사한다. 요청이 맞아도 과거 gold 주석 해시가 없으면 주석의 역사적 동일성은 미확정이다. 진단 시 사건 오류가 있으면 `replay_bad_events`로 남기고 완전한 재현으로 인정하지 않는다.

오프라인 경로는 모델을 호출하지 않는다. 후속 `replay`에도 같은 원칙을 적용한다. 캐시가 없거나 요청·데이터 대응을 확인할 수 없으면 `replay`를 불가로 기록한다. 새 호출로 자동 보충하지 않는다. 현재 프롬프트로 과거 캐시 키를 재생성하는 것만으로 과거 요청이 같았다고 가정하지 않는다.

과거 보고서의 `reason`이 실행기가 기록한 `ERROR:` 형식이면 실패로 분류한다. 나머지는 기존 필드의 타입·범위를 검증하고, 원본 응답 없이는 확인할 수 없는 형식 문제를 별도 표시한다. `bad_events`가 남아 있는 C/D 결과는 새 완전성 기준에서 미완료로 분류하고, 과거 점수도 보존한다. 원본이 없으면 유효성을 완전히 검증했다고 쓰지 않는다.

보고서에는 원본 파일·해시, 조건·trial·모델, 포함 항목 목록, 평가 버전, 분석 시각, 데이터 대응 상태, 누락 자료, 실패 분류의 출처를 기록한다. 선택한 보고서를 명시적으로 받으며 파일 이름의 최신 순서만으로 서로 다른 trial을 합치지 않는다.

## 헛경보 원인표

첫 분석은 v3 dev의 정상판 C/D 경고를 대상으로 한다. 추출 누락이 만들어낸 잘못된 상태도 함께 확인한다. test에서 이미 본 사례는 회귀 진단에 사용할 수 있지만 이후 미열람 평가라고 부르지 않는다.

각 행에 다음을 기록한다.

| 필드 | 내용 |
|---|---|
| 식별 | 원본 보고서, scene/item ID, 조건, trial, 경고 문장 |
| 관측 | 본문 구절, 정답 사건, 추출 사건, 위반 직전 관련 상태 |
| 원인 | `extraction`, `rules`, `ambiguous_text`, `annotation`, `unresolved` |
| 판단 | 주원인 하나, 필요하면 보조 원인, 판단 근거 |
| 상태 | 미검토/검토 완료, 검토자, 검토일 |
| 후속 | 수정 후보 또는 확인할 질문, 재현 사례 |

오류 메시지에 `hand_full`이 있다는 이유만으로 규칙 오류라고 분류하지 않는다. 추출 사건을 고쳤을 때 해결되는지, 사건은 그대로 두고 규칙 해석을 고쳤을 때 해결되는지 검토한다. 판단할 자료가 부족하면 `unresolved`로 남긴다.

같은 추출 오류가 여러 후속 경고를 만든 경우 경고 수와 독립 원인 수를 따로 집계한다. 사람 검토 전에 자동 생성한 목록을 완성된 원인 분석 결과로 표시하지 않는다.

## 실험 해석과 채택 기준

- 정상/오류 변형은 원본 장면 단위로 묶어 분할한다. 같은 장면의 패러프레이즈도 같은 분할에 둔다.
- 개별 비율에 Wilson 구간을 표시하되, 오류판들이 같은 장면을 공유한다는 한계를 함께 적는다. 조건 비교의 불확실성은 장면 단위 paired bootstrap 등으로 추정한다.
- 반복 실행은 같은 설정과 항목으로 비교한다. 실패를 제외한 조건부 성능과 전체 기준 성능을 함께 본다.
- 현재 test를 보며 설계를 바꾼 뒤의 최종 채택 판단에는 별도의 미열람 평가 세트를 쓴다. 기존 test 데이터는 역사적 재현과 회귀 확인을 위해 고정한다.
- 기존 목표(재현율 0.8 이상, 헛경보율 0.1 이하, Canon 검수 이내 비용)는 제안값이다. 새 목표 후보는 전체 기준 정답 문장 검출률 0.8 이상과 완료 기준 헛경보율 0.1 이하이며, 완료율과 신뢰구간을 함께 평가한다.
- 최소 완료율과 신뢰구간 기반 채택 경계는 dev에서 정하고 최종 세트를 보기 전에 고정한다. 단일 실행의 점추정만으로 성공을 선언하지 않는다.
- 비용에는 시작 상태 생성·재시도를 포함한다. 캐시 재사용 비용과 실제 새 호출 비용을 구분하고, 과거 가격을 현재 가격으로 표시하지 않는다.

첫 적용 결과와 남은 불확실성은 [P1/P2 분석 보고서](analysis/2026-11-14-p1-p2.md)에 있다.
