# P2 후속 검토와 P3 규칙 수정 계획

상태: 계획 작성 완료, 구현 대기. 2026-11-15 (KST).

목표는 본문에 명시된 손과 물체를 보존하면서, 불확실한 정보 때문에 생기는 헛경보를 줄이는 것이다. [전체 실행 계획](../plan.md)의 P2 후속 검토와 P3를 실행 단위로 나눈다. 상태의 의미는 [모듈 설계](../design.md), 지표는 [평가 명세](../evaluation.md), 관측 근거는 [P1/P2 분석](../analysis/2026-11-14-p1-p2.md)을 따른다.

이 문서의 기대 동작과 체크리스트는 앞으로 검증할 계약이다. 현재 구현의 통과 결과를 뜻하지 않는다. 프롬프트·평가 공식·정답 데이터는 규칙 변경과 동시에 바꾸지 않는다.

## 출발점과 진행 조건

P1 평가 분리와 P2 오프라인 명령은 구현됐다. 정상판 경고 50항목 중 29항목은 Codex가 원인 후보를 기록했고, 21항목은 미해결이다. 모든 원인 후보는 사람의 확정 검토 전 상태다. 분석에서 사용한 H/O 등의 ID는 반복 패턴의 이름이며 확정한 독립 원인 건수가 아니다.

명시적인 사건 계약 위반은 최소 사건열로 재현해 먼저 수정할 수 있다. P2 전체의 사람 검토 완료를 모든 P3 작업의 선행 조건으로 두지 않는다. 반대로 생략된 취득·접촉 종료처럼 본문 해석이 갈리는 사례는 주석 정책을 확정하기 전까지 정상 동작의 정답으로 고정하지 않는다.

| 작업 | 의존성 | 산출물 | 상태 |
|---|---|---|---|
| P3-0 기준선·재현 사례 준비 | P1/P2 도구 | 변경 전 코드 식별 정보, 최소 재현 목록, 비교 대상 목록 | 대기 |
| P3-1 명시적 손 관측 | P3-0 | `state.hand` 보존과 충돌 검증 | 다음 구현 |
| P3-2 물체 동일성과 해제 | P3-0 | 물체 오인·다른 물체 해제 방지 | 대기 |
| P3-3 미확정 손 배정 | P3-1, P3-2 | 가능한 손 배정 유지, 관련 상태 표현 설계 | 대기 |
| P3-4 장소 비교 | P3-2 | 같은 장소·다른 장소·미확정 구별 | 대기 |
| P3-5 규칙 전후 비교 | 각 수정 묶음마다 | 변경 항목 목록, 완료율·검출률·헛경보 비교 | 대기 |

순서는 P3-0 → P3-1 → P3-2 → P3-3 → P3-4다. P3-5는 각 묶음의 완료 검사이며 마지막에 한 번만 수행하는 작업이 아니다. 소요 시간은 재현과 영향 범위를 확인한 뒤 정한다.

## P3-0. 기준선과 최소 재현

기존 결과에는 당시 규칙 버전이 없는 경우가 있다. 과거 보고서와 새 규칙을 바로 비교하지 말고, 수정 직전 작업 트리의 코드로 동일 캐시를 판정한 결과를 새 기준선으로 기록한다. 현재 미커밋 코드도 있으므로 Git 커밋만으로 버전을 식별하지 않는다.

- [ ] `rules.py`와 사건 변환 모듈의 해시, 평가 버전, 데이터·캐시 해시, 조건·trial을 기록한다.
- [ ] 사례마다 시작 상태, 사건열, 현재 결과, 기대 결과와 그 근거를 적는다.
- [ ] 실제 본문 해석 없이도 판정 가능한 최소 사건열을 `tests/test_rules.py`의 회귀 테스트로 만든다.
- [ ] 헛경보 사례마다 반드시 오류가 나야 하는 대조 사례도 둔다.
- [ ] 로컬 `results/`가 없어도 최소 재현과 테스트가 실행되게 한다.

대상은 우선 dev에서 확인한 H(명시적 손 무시)와 O(물체 동일성·해제)다. 기존 test 세트는 고정 회귀 확인에만 쓰며 새 설계를 고르는 개발 데이터로 확대하지 않는다.

## P3-1. 명시적 손 관측

근거: `Opus/D/v3d02-clean`의 오른손 우산이 왼손에 저장되는 사례와 `Gemini/C/v3d11-clean`의 열쇠 관측·해제. 현재 `Scene._ev_state`의 보유 관측은 사건의 `hand`를 검사하지 않고 미지인 손 하나를 선택한다.

변경 중심은 `shadowcast/rules.py:Scene._ev_state`와 `tests/test_rules.py`다. 사건 변환이 `hand`를 유지하는지도 관련 테스트로 확인한다. 단순히 선택 순서를 뒤집는 것으로 해결하지 않는다.

| ID | 입력과 대조 | 기대 동작 |
|---|---|---|
| H1 | 양손 미지 → 오른손 우산 보유 관측 → 왼손 사용 | 오른손에 우산 보존, 왼손 사용에 헛경보 없음 |
| H2 | H1 이후 오른손에 다른 물체 취득 | 명시적 점유 충돌 검출 |
| H3 | 오른손 빈손 확정 → 오른손 우산 보유 관측, 취득 사건 없음 | 관측으로 취득을 만들어내지 않음; 암묵적 취득 허용은 별도 계약 |
| H4 | 왼손 우산·오른손 빈손 확정 → 오른손 우산 보유 관측 | 손을 몰래 바꾸거나 동일 물체를 복제하지 않음; 충돌 검출 |
| H5 | 오른손 우산 관측 → 오른손 우산 해제 | 정확한 손이 해제되고 다른 손의 물체는 유지 |

H3/H4의 명시적 상태와 모순인 관측은 해당 손 상태를 덮어쓰지 않아야 한다. 미확정 손을 좁히는 처리는 P3-3에서 확장한다. 완료 시 관측 전후 상태와 경고를 함께 검사한다.

## P3-2. 물체 동일성과 해제

근거: `v3d06-clean`에서 `냄비`와 `육수 냄비`가 같은 물체로 취급되고, 이후 `release(any)`가 수세미까지 비우는 연쇄. 같은 원인 유형 안에서도 이름 비교 문제와 해제 대상 선택 문제를 별도 테스트로 분리한다.

변경 중심은 `_same`, `Scene.name`, `holders`, `_release` 및 이들을 호출하는 취득·건네기 경로다. 기존 `_same` 호출부에 이름 매칭이 쓰이는 범위를 확인하고, 장소 비교는 P3-4의 별도 계약을 따른다.

| ID | 입력과 대조 | 기대 동작 |
|---|---|---|
| O1 | 인물 A의 냄비, 인물 B의 육수 냄비 | 부분 문자열만으로 A의 손을 비우지 않음 |
| O2 | 칼을 들고 칼집을 해제 | 칼 점유 보존, 칼집 보유 여부에 맞는 진단 |
| O3 | 오른손 수세미, 왼손 빈손 → 냄비 `release(any)` | 수세미를 대신 지우지 않음 |
| O4 | 손에 수세미 → 같은 손을 명시해 냄비 해제 | 손 지정만으로 물체 불일치를 무시하지 않음 |
| O5 | 별칭으로 동일하다고 제공된 두 이름 | 같은 물체로 취급하고 정상 취득·해제 가능 |
| O6 | 하나의 양손 물체와 양손에 하나씩 든 동종 물체 | 해제 후 남는 점유가 각각의 의미와 일치 |

이름이 다르다는 사실만으로 실제로 다른 물체라고 모두 단정하지 않는다. 명시적 동일성 근거 없이 다른 인물의 점유를 옮기거나 지우지 않는 것이 첫 변경의 목표다. 추출기가 서로 다른 스틱을 하나로 표현한 N 유형은 규칙 수정만으로 해결됐다고 기록하지 않는다.

현재 `failed`, `loose`, `let_go`, `pairs`가 후속 해제에 영향을 준다. 실패한 취득 뒤의 해제, 착용 해제 뒤의 물체, 사람 접촉 해제를 함께 점검한다. 이 보조 상태의 의미를 일괄 삭제하거나 모든 사건 실패의 상태 정책을 이 작업에서 재정의하지 않는다.

## P3-3. 미확정 손 배정

`hand=any`를 특정 손에 확정한 뒤 나중에 임의로 옮기는 대신, 알려진 점유 수와 가능한 배정을 유지한다. [설계의 네 손 사례](../design.md#손의-미확정-상태)를 기본 계약으로 사용한다.

구현 전에 다음을 기록한다.

- [ ] 인물별 두 손의 가능한 배정 표현과 명시적 관측에 따른 좁힘 방식.
- [ ] 미지 손과 물체는 알지만 손만 미확정인 상태의 차이.
- [ ] 취득·해제·건네기·양손 물체·접촉에 적용할 갱신 규칙.
- [ ] 다른 인물과 연결되는 제약을 잃지 않는 범위와 계산량 한도.
- [ ] `snapshot`과 기존 채널 집계가 미확정 상태를 어떻게 표현하는지 및 결과 형식 호환성.

가능한 배정 모두가 충돌할 때만 확정 위반으로 판정한다. 지원하지 못하는 조합을 `no_error`로 바꾸거나 경고를 통째로 지우지 않는다. 처리 한계를 결과 계약에 연결해야 한다면 `runner.py` 통합과 평가 테스트를 이 묶음에 포함하고 변경 범위를 문서화한다.

## P3-4. 장소 비교

현재 `same_place`의 공유 단어 기반 비교를 점검한다. `민준 왼쪽 주머니`와 `민준 오른쪽 주머니`는 구별하고, `바지 주머니`와 `민준 바지 앞주머니`처럼 정보가 덜 구체적인 관계는 즉시 모순으로 확정하지 않는다.

완료 기준은 정확한 장소·명시적 별칭의 동일성, 명시적 좌우/소유자 충돌, 미지/덜 구체적인 장소의 세 부류가 각각 검증되는 것이다. 기존 `test_place_names_match_on_a_shared_word`가 의도한 정상 사례와 과도한 동일성 허용을 나눠 검토한다. 테스트 기대값 변경에는 계약상 이유를 남긴다.

## P3-5. 동일 추출 응답으로 전후 비교

현재 `rescore`는 저장 예측의 재채점이고, `audit`는 정상판 경고만을 대상으로 한 진단이다. **둘만으로 전체 오류판을 포함한 규칙 개선 성능을 측정할 수 없다.** 독립 `replay` 명령은 아직 구현되지 않았다.

전체 비교를 위해 `analysis.py`의 읽기·요청 검증·사건 변환을 재사용하는 오프라인 재실행 경로를 별도 구현한다. CLI 이름과 인자는 그 구현에서 확정하고, 구현 전에는 존재하는 명령처럼 안내하지 않는다.

- [ ] 선택한 보고서의 C/D 전체 항목을 대상 목록으로 고정한다. 과거에 경고한 정상판만 선택하지 않는다.
- [ ] 변경 전후에 같은 본문·시작 상태·원본 추출 응답·정규화 사건열·평가 버전을 사용한다. 변환 코드도 바꾸었다면 규칙만의 효과라고 부르지 않는다.
- [ ] 캐시 누락·전체 요청 불일치·형식/의미 오류는 별도 상태로 남긴다. 네트워크로 보충하지 않는다.
- [ ] 전체 시도 항목과 유효 대응 항목 수를 모두 보고한다. 미대응 항목을 정상 판정으로 세지 않는다.
- [ ] 경고가 사라진 항목, 새로 생긴 항목, 위치가 바뀐 항목을 모두 본문·전후 상태와 연결한다.
- [ ] 완료율, 전체 기준 정답 위치 검출률, 완료 정상판 헛경보율을 분모와 함께 제시한다.
- [ ] 기존 보고서·캐시를 보존하고 전후 코드 해시와 비교 대상 목록을 별도 결과에 남긴다.

진단용 `snapshot`은 모든 보조 상태를 직렬화하지 않는다. 중간 snapshot에서 이어 실행하지 않고 시작 상태와 전체 사건열로 재실행한다. 역사적 규칙과의 불일치는 기록하되 새 기준선과 수정본의 비교에서 개선량으로 섞지 않는다.

## P2에서 남은 검토

| 대상 | 수 | 필요한 후속 근거 | 종료 조건 |
|---|---|---|---|
| X: 과거 결과와 현재 규칙 불일치 | 15항목 | 당시 코드 식별 정보 또는 동일 응답으로 당시 결과 재현 | 확인되면 역사적 재현 결과 기록, 불가하면 사유를 유지하고 새 기준선과 구별 |
| F: 추출/사건 불완전 | 5항목 | 원본 응답의 누락 필드·의미 오류 및 유효성 기준 | 실패 원인 기록; 임의 보정 없이 성능 판정 미완료로 유지 |
| U: `both`와 추가 빈손 수 계약 | 1항목 | 도구를 쥔 손과 새로 필요한 빈손을 구별한 정상/오류 대조 | 사건 스키마와 규칙 계약 결정 후 회귀 사례 추가 |
| 원인 후보 | 29항목 | 사람의 본문·추출·상태 검토, 필요한 경우 한 변수만 바꾸는 재현 | 검토자·근거·원인·변경 결론 기록 |

검토 기록은 원본 audit를 덮어쓰지 않는다. 원본 보고서·항목·조건·trial·경고 문장으로 연결하며 `unreviewed`, `agent_preliminary`, `human_reviewed`, `unresolved`를 구별한다. 이는 검토 기록의 권장 상태이며 현재 CLI가 모든 전환을 제공한다는 뜻은 아니다.

사람 검토 대상에는 I(암묵적 취득), L(점유 종료 생략), U(양손 사용)가 우선 포함된다. 관측을 취득으로 바꾸면 경고가 사라진다는 사실만으로 추출 오류라고 확정하지 않는다. 원인 후보 유형 수, 검토 완료 항목 수, 독립 원인 건수는 따로 기록한다.

## 검증과 완료 기록

수정 중에는 영향을 받는 규칙 테스트를 실행한다. 한 묶음이 준비되면 전체 단위 테스트와 데이터 검증을 수행하고, 손/물체 상태가 바뀐 경우 v3 dev+test 정답 사건의 C/D 회귀를 확인한다. 통과 후 변경이나 새 우려가 없으면 반복하지 않는다.

```bash
python3 -m unittest discover -s tests -p 'test_rules.py'
python3 -m unittest discover -s tests
python3 -m shadowcast validate data/*.json
```

정답 사건 회귀는 `run --backend gold --conditions C,D`에 두 v3 데이터 파일과 새 임시 결과 경로를 지정한다. 완료율·정답 위치 검출률 1, 헛경보율 0을 확인한다. 단, 정답 사건 만점만으로 실제 추출 응답에서의 개선을 선언하지 않는다.

각 작업의 완료 기록에는 변경 파일, 최소 재현/대조 결과, 기존 테스트 영향, 전후 분석 결과 위치, 미해결 항목을 남긴다. 기존 gold와 충돌하면 주석 오류인지 계약 변화인지 먼저 설명하고 정답을 점수에 맞춰 고치지 않는다. 원인이 불명확한 회귀가 남으면 해당 변경을 완료로 표시하지 않는다.
